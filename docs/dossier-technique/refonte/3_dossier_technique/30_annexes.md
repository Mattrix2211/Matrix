# Annexes : totaux, méthode et accès

<div class="ligne-public"><b>Public :</b> développeurs, mainteneurs, exploitants · <b>Accès restreint</b> · <b>Ce que vous y trouverez :</b> ce que contiennent les annexes consultables, comment elles sont générées et les totaux de contrôle</div>

## Pourquoi des annexes hors du PDF

Les inventaires détaillés (routes, modèles, variables, matrice de couverture, éléments non vérifiés) sont consultés par recherche et par tri, pas lus de bout en bout : ils sont fournis sous forme d'**un fichier HTML autonome** et de **fichiers CSV** (UTF-8, séparateur « ; »), dans le dossier des annexes consultables. Le fichier HTML ne demande aucune connexion et aucune police distante ; chaque fichier porte la mention provisoire. Le PDF ne garde que les totaux, la méthode et les extraits ci-dessous.

| F5 | **Registre des éléments non vérifiés ⚪** : un passage par ligne, document, section et étiquettes ; généré depuis les sources |
| G1 à G7 | Matrice de couverture (modèles, routes, tâches, commandes, actions, circuits, dépendances) |
| H1 | Index des schémas |

## Méthode

1. L'inventaire du code de l'état B est généré par script (modèles, routes, tâches, commandes, actions, modules, signaux, dépendances).
2. Les tables sont écrites en CSV puis incorporées au fichier HTML par le script de génération des annexes consultables.
3. Le registre des éléments non vérifiés est reconstruit à chaque génération en parcourant les sources des trois documents ; aucune ligne n'est saisie à la main.
4. Contrôles : le fichier s'ouvre hors ligne sans aucune requête réseau, le filtre et le tri répondent, la mise en page tient à 1024×768 et 1366×768, les totaux égalent le registre des faits.

## Limites ⚪

- Les numéros de chapitre de la matrice de couverture (G6) sont ceux de l'édition initiale ; la correspondance avec les documents actuels est dans le fichier de correspondance de la refonte.
- Les annexes décrivent l'état B ; elles ne valent pas validation du logiciel.
